## 一、核心思想：DDD Lite vs 经典 DDD

| 项目 | 经典 DDD | DDD Lite（本方案） |
|------|----------|-------------------|
| 聚合根 | 单独 Aggregate 类 | **Entity 类**（可标 `@TableName`） |
| 包结构 | `domain/aggregate/` | `domain/entity/` |
| 术语 | Aggregate / Entity / ValueObject | Entity / ValueObject |

**「聚合根」是角色描述，不是类名或包名。** 禁止 `XxxAggregate` 类与 `domain/aggregate/` 包。

## 三、分层职责

### 3.1 interfaces（接口层）

**Controller 只做 4 件事**：接收参数 → 校验参数 → 调用 Handler → 返回结果。

```java
@RestController
@RequiredArgsConstructor
public class PartnerManagementController {
    private final CreatePartnerHandler createPartnerHandler;

    @PostMapping
    public Result<PartnerResponse> create(@Valid @RequestBody CreatePartnerRequest request) {
        return Result.ok(createPartnerHandler.execute(request));
    }
}
```

### 3.2 application（应用层）

**Handler = 用例编排**：加载实体 → 调用 Entity 业务方法 → 持久化 → 发布事件 → 返回。

```java
@Component
@RequiredArgsConstructor
public class ActivatePartnerHandler {
    private final PartnerRepository partnerRepository;
    private final ApplicationEventPublisher eventPublisher;

    @Transactional(rollbackFor = Exception.class)
    public PartnerResponse execute(Long partnerId) {
        PartnerEntity partner = partnerRepository.requireById(partnerId);
        Integer oldStatus = partner.getStatus();
        partner.activate();                          // 业务逻辑在 Entity
        partnerRepository.save(partner);
        eventPublisher.publishEvent(
            new PartnerStatusChangedEvent(this, partnerId, oldStatus, partner.getStatus()));
        return PartnerAssembler.toResponse(partner);
    }
}
```

### 3.3 domain（领域层）

**仅含** `entity/`、`valueobject/`、`repository/`、`event/`（+ 跨模块 `port/`）。**无 `service/`**。

- 单实体规则 → `XxxEntity` 方法
- 同模块跨实体编排 → Handler
- 跨模块协作 → Port 接口或领域事件

```java
@Data
@EqualsAndHashCode(callSuper = true)
@TableName("boss_partner")
public class PartnerEntity extends BaseEntity {
    private Long id;
    private String code;
    private Integer status;

    // 工厂方法
    public static PartnerEntity create(String code, String name) {
        if (code == null || code.trim().isEmpty()) {
            throw new BusinessException(ResultCode.BAD_REQUEST, "编码不能为空");
        }
        PartnerEntity p = new PartnerEntity();
        p.code = code.trim();
        p.status = 0;
        return p;
    }

    // 状态转换
    public void activate() {
        if (this.status != null && this.status == 1) {
            throw new BusinessException(ResultCode.BUSINESS_ERROR, "已激活");
        }
        this.status = 1;
    }

    // 业务判断
    public boolean isActive() { return this.status != null && this.status == 1; }
}
```

> Entity 必须包含 ≥3 类业务方法：工厂方法、状态转换、业务判断/计算。Entity 不依赖 Spring（不 `@Autowired`）。

### 3.4 infrastructure（基础设施层）

`RepositoryImpl` 实现 domain 的 Repository 接口，负责 Entity ↔ PO/Mapper 转换；禁止 Repository 返回 PO。

```java
@Repository
@RequiredArgsConstructor
public class PartnerRepositoryImpl implements PartnerRepository {
    private final PartnerMapper partnerMapper;

    @Override public PartnerEntity findById(Long id) { return partnerMapper.selectById(id); }
    @Override public void save(PartnerEntity p) {
        if (p.getId() == null) partnerMapper.insert(p);
        else partnerMapper.updateById(p);
    }
}
```

## 四、硬约束（P0，违反即拒绝生成代码）

| # | 规则 |
|---|------|
| 1 | 禁止新增 `service/`、`service/impl/`、`XxxService`、`XxxApplicationService` |
| 2 | 文档必须含可追溯元数据（类型/编号/版本/状态/模块/所有者/完成人/Agent/模型/时间/关联） |
| 3 | 单文件 ≤ 300 行（Port/PortImpl/RepositoryImpl/Mapper ≤ 500 行豁免；Handler ≤ 100 行；方法 ≤ 30 行） |
| 4 | 新增领域实体必须放 `domain/entity/`，禁止裸 `entity/` |
| 5 | 源文件 UTF-8 无 BOM |

### 对象落位决策树

```
这个对象是否有独立身份、状态和业务行为？
├── 是 → 领域实体 domain/entity/XxxEntity
└── 否
    ├── 不可变业务概念（金额/编号/时间区间）？→ domain/valueobject/（无 VO 后缀）
    ├── 只是数据库映射或复杂 SQL 查询结果？→ infrastructure/（XxxPO / XxxRow）
    └── 只是 HTTP/消息契约？→ interfaces/（Request / Response / VO）
```

### 命名对照

| 类型 | 命名 | 位置 |
|------|------|------|
| Entity | `{Business}Entity` | `domain/entity/` |
| 值对象 | `{Concept}`（如 `Money`、`AgentId`） | `domain/valueobject/` |
| 视图对象 | `{Business}VO` | `interfaces/vo/` |
| Handler | `{Action}{Business}Handler` | `application/handler/` |
| Repository | `{Business}Repository` | `domain/repository/` |
| RepositoryImpl | `{Business}RepositoryImpl` | `infrastructure/persistence/repository/` |
| PO | `{Business}PO` | `infrastructure/persistence/po/` |
| Mapper | `{Business}Mapper` | `infrastructure/persistence/mapper/` |
| 事件 | `{Business}{Action}Event` | `domain/event/` |
| Port | `{Business}{Action}Port` | `domain/port/`（或共享模块 port） |
| Request/Response | `{Action}{Business}Request` / `{Business}Response` | `interfaces/request/`、`interfaces/response/` |

**禁止后缀**：`BO`、`DO`、`Model`、`Bean`、`Manager`、`Util`、`Info`、`Data`。

## 五、禁止模式（Anti-patterns）

1. **Handler 调用 Handler** —— Handler 是用例入口，非可复用组件；共享逻辑抽 Helper/Port/Entity。
2. **Entity 依赖 Spring** —— 依赖通过参数传入，Entity 是纯业务对象。
3. **Controller 含业务逻辑** —— 只做 4 件事。
4. **跨模块直接依赖** —— 用事件或 Port 接口，禁止 `@Autowired` 别的模块 Service/Mapper。
5. **假 Handler** —— 空壳转调 Service（业务逻辑须下沉 Entity）。

## 六、跨模块通信

| 场景 | 手段 |
|------|------|
| 异步通知 | 领域事件：`@Transactional` 内 `publishEvent` → 对方 `@EventListener` |
| 同步查询 | Port 接口：调用方在 `domain/port/` 定义，Provider 模块实现 |

```java
// boss-order 发布
eventPublisher.publishEvent(new OrderCreatedEvent(this, order.getId(), order.getAmount()));
// boss-commission 监听
@EventListener @Transactional
public void onOrderCreated(OrderCreatedEvent event) { /* 计佣 */ }
```

## 七、Java 版本约束

**当前 Java 8**：禁用 `record`、`var`、`sealed`、Pattern Matching；Request/Response/VO 用 `@Data class`；值对象用 `final class`/`enum`。

**2027-Q1 升级 Java 17 后**：Request/Response/值对象可改 `record`；Entity/PO 仍用 `class`（需继承 BaseEntity）。
