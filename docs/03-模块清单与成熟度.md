## 一、成熟度级别定义

| 级别 | 定义 | AI 策略（新功能） |
|------|------|-------------------|
| **L3** | DDD Lite 标准参考 | 严格 Handler + 充血 Entity + `domain/entity/` |
| **L2** | 业务模块目标态 | 新功能必须 Handler + Entity |
| **L1** | 系统模块 | 默认 controller/service/mapper，不强制 Handler |

## 二、接线口径（避免「100%」歧义）

| 口径 | 定义 | 验收 |
|------|------|------|
| **A：Controller 直调** | Controller 内调用 `XxxHandler.execute()/.handle()` | ✅ 目标态 |
| **B：Service 委托** | Controller → Service → Handler | ⚠️ 过渡态，须登记债务 |
| **C：Handler 存在** | 仅创建了 Handler 类 | ❌ 不算完成 |

**假 Handler**：Handler 内只注入 `XxxService`、无 Repository/Port —— 须逐步消除。

## 六、双轨物理迁门禁

存量 Entity「双轨」（领域模型 + 持久化 PO）迁入物理目录前须满足：

1. 该类型跨模块 Entity+Mapper import = 0
2. 模块内主写路径已走 domain / Converter / Repository
3. 守卫 + Spec 绿

禁止未过门禁的整仓搬迁。
